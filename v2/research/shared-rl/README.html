HRL 0.10 shared R/L dark-edge research

This continuation replaces the two learned native/full R/L banks with one bank per candidate, applied after the same deterministic, own-gamut boundary normalization. Earlier releases and separate refits remain unchanged.

The public meanings stay fixed: K = 1 - L, W = L - R, and chromaticness is R. The internal ratio U = R/L is not Reach itself. Level is brilliance / inverse blackness, not relative Y or an ordinary lightness correlate. R=L is the zero-whiteness black-to-vivid edge.

Use

import {createSharedHRL, ADOBE_RGB1998} from './source.mjs';
const native = await createSharedHRL({gamut:'srgb', checkpoint:'balanced'});
const full = await createSharedHRL({gamut:'full', checkpoint:'balanced'});
const third = await createSharedHRL({gamut:ADOBE_RGB1998, checkpoint:'balanced'});
const q = native.fromRGB([0.2,0.3,0.4]);
const xyz = native.toXYZ(q);

The selected gamut determines the actual physical boundary and own-anchor normalization. It does not select a second coefficient bank or a learned gamut-specific correction. source.mjs accepts a linear-RGB-to-XYZ matrix descriptor and computes its source chart without observer fitting. Only sRGB and full contributed to the joint fit. Adobe RGB (1998) is the untrained numerical transfer test. This is not proof of perceptual accuracy for all gamuts. Canonical Display P3 is currently rejected because its red primary slightly exceeds the inherited polygonized boundary; no silent clipping or P3 support claim is made.

The built-in source atlases are caches, not independently fitted heads. source-test.mjs rebuilds both with the same path-integration algorithm and checks their agreement. The same normalized source coordinates yield bit-identical final R/L across the two realizations.

Dark-side correction

The inverse tonal correction is phi(t) = t - a(H,U) t (1-t)^2, with a = 0.85 sigmoid(Fourier(H)) U^2. Its derivative in t is at least 0.15. It fixes black, the top boundary, the neutral side and the zero-whiteness edge. Safeguarded inversion is used in the forward map. Four invertible coupling layers retain position- and hue-dependent interactions.

The shape and endpoint-normalized Oklab diagnostic target are engineering responses to Coonie's screenshots, not new observer measurements or replacements for Level's definition. Positive Jacobians, visually regular contours and low difference error are separately evaluated. Apparent folds in screenshots alone did not establish a negative Jacobian.

Results and status

The recovered frozen records retain their pre-interruption coefficients. The shared balanced trial's recorded weighted COMBVD estimates are approximately 32.1164 (sRGB) and 31.4490 (full); the shared metric alternate's are 29.3180 and 29.6309. These are worse than the separately fitted predecessors. See the actual runtime results/REPORT.md and results/verification.json after verification; do not treat recorded optimizer estimates as newly verified results.

The dark-edge change and shared-bank architecture are the purpose of this checkpoint. It is a review candidate, not an approved replacement. All clipping, rejected samples, full-only/common COMBVD subsets and inherited hue-continuation limits are reported separately. Only the five scored generation and sixteen scored measurement ColorBench columns are run. No overall rank is asserted from incompatible support.

D65, relative XYZ, referenceWhiteNits:300, and explicit Bradford source-white adaptation remain. The full reference solid covers the polygonized physical cone for 0 <= relative Y <= 1, not unlimited absolute luminance. Existing absolute/relative unit conversions and the extended carrier remain available.

Reproduction

Use the pinned ColorBench commit 12b2de215cc5020682e3d245a8c78bce5f0ebbc9 and pool commit 8641f4e8ebd9d85a34dc0fedc116fa0e58493190. The completion workflow prepares training pairs from the retained raw XYZ NPZ, generates adapters and exact source-coordinate caches, runs numerical checks and scored evaluations, then tests and publishes the page. The fitting script additionally needs PyTorch and the dense cache generated by cache.mjs; it writes new trial records and traces.

python v2/research/shared-rl/prepare.py
node v2/research/shared-rl/cache.mjs --coordinates-only
node v2/research/shared-rl/source-test.mjs
node v2/research/shared-rl/test.mjs
python v2/research/shared-rl/benchmark.py --colorbench /path/to/colorbench --pool /path/to/color-perception-datasets/datasets
GAMUT=srgb DENSE=1 node v2/research/shared-rl/visual.mjs old-balanced balanced metric
GAMUT=full DENSE=1 node v2/research/shared-rl/visual.mjs old-balanced balanced metric
node v2/research/shared-rl/audit.mjs old-balanced balanced metric
