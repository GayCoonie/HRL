HRL v2: A Smooth

Approved prototype: OPAL 0.8 A / Smooth. The model is the unchanged Smooth R/L-only checkpoint from HRL_A_RL_Branches.zip, selected by Coonie for publication. This is not a new hue-ring fit and is not a declaration of stable Release 2.

Open the standalone picker · Publication checks · All COMBVD subsets · Exact numerical definition

The page and createASmooth() default to Smooth. A parent is retained for comparison. Release 1's root picker, src/, existing v2 modules, and earlier prototype pages are not replaced.

Use

import {createASmooth} from './v2/a-smooth/index.mjs';

const hrl = await createASmooth(); // native sRGB, approved Smooth
const q = hrl.fromRGB([0.2, 0.5, 0.8]);
const rgb = hrl.toRGB(q);
const xyz = hrl.toXYZ(q);
const d = hrl.distance(q, {H: 270, R: 0.4, L: 0.7});

const full = await createASmooth({gamut: 'full'});
const sameStimulus = full.fromXYZ(xyz);
const parent = await createASmooth({gamut: 'srgb', variant: 'parent'});

Coordinates obey 0 <= R <= L <= 1; H is in degrees. The picker can display R/L as 0–175.75 while the API remains normalized. gamut:'full' means the existing bounded, D65-relative full-domain construction, not Rec.2020 and not an HDR extension. Use XYZ or pseudo-RGB for the full model; its unsupported native-sRGB output methods throw rather than silently clip.

Every profile uses the actual regular equilateral-bicone distance:

E(H,R,L) = [L - R/2, sqrt(3)/2 * R*cos(H), sqrt(3)/2 * R*sin(H)]
DeltaE(a,b) = length(E(a) - E(b))

Convert H to radians for sine and cosine. No Cartesian distance between raw H/R/L triples is used.

Frozen definition and provenance

The 260 R/L coefficients, one shared neutral parameter, two coupling layers, six angular harmonics, and cap of 8 are copied numerically without rounding or optimization. Both installed records have ring_logits:null. Hue identities, Release 1 angle attachment, physical hue sheets, and vivid endpoints are unchanged. The complete field and existing source code remain in ../lib/ and ../data/.

definitions.json is a runtime extraction of the original checkpoint records. Optimizer trajectories and unrelated trials are omitted from this deployment; original record hashes, the supplied archive hash, expected masks, and baseline scores are retained. No result is claimed to be a newly fitted model.

The approved Smooth source record SHA-256 is:

28bb76cea73d2d5a30167c9b582969994ca11db10f3d58e0b8e53b0f3038f555

The two large source atlases are regenerated by the original deterministic construction, not refitted, and must match the supplied archive byte-for-byte before publication:

full  ae3da2b76af61b2aaba72054f6694f304ad6d14c03566054ebf98cad0545403c

The shared observer field and original angle file are also hash-checked. The mathematical R/L runtime is retained from opal-free.mjs; only its unused legacy loader and imports are replaced by the named, publication-specific factory.

The publication gate evaluates continuous adapted XYZ through the actual JavaScript model. It checks the exact original retained-pair mask hashes, original-ring correspondence, random coordinate and integer round trips, gray values, and black/white endpoints. It writes fresh per-subdataset scores plus full-model scores on the common 3,331-pair set to verification.json and COMBVD.csv.

Traditional pooled COMBVD multiplicities are BFD-P 1, LEEDS 9, RIT-DuPont 9, WITT 7, with one pooled scaling factor. Subdataset scores have their own descriptive scale; the pooled score is not an average of those rows. These are development results on evidence used in fitting, not independent validation. Smoothing is geometric regularization, not an additional human-observer dataset.

Reproduce

Node 22.16.0 was used for publication. There are no npm dependencies for conversion, regeneration, or the numerical checks.

node v2/a-smooth/build-atlas.mjs   # verify existing tables or regenerate exactly
node v2/a-smooth/test.mjs          # exact masks, COMBVD and numerical invariants
node v2/a-smooth/build-viewer.mjs  # standalone v2/a-smooth.html

Use --force with the atlas builder to regenerate even when verified tables already exist. The builder rejects changed source hashes. Do not relax this check to publish a different numerical definition under the same name.

The generated viewer runs offline as a single HTML file. For modular browser imports, serve the repository over HTTP or use GitHub Pages. The complete source tables are committed, so normal usage does not regenerate them.

Known follow-up: magenta

Coonie accepted A Smooth while noting that the magenta sheet still looks unusual. Its cause is not established by this publication. This is deliberately left unchanged for later investigation; no hue, R/L, boundary, or clipping adjustment has been smuggled into the selected version.

The underlying experimental hue field, gamut limits, source appearance assumptions, and inherited extrapolation limitations remain those of the supplied A source. Publication does not improve their empirical validation by itself.
